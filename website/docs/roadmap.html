What's next

Roadmap

Tracks under consideration. Nothing here is committed work. An item moves to "in progress" only when the owner approves a follow-up SPEC document for it. The full ROADMAP.md lives in the repo.

Track 1

SaaS pivot

Convert the personal toolkit into a multi-user product where strangers sign up, run the workflow on their own JDs, and download their own deliverables.

Cost ladder: $0 hobby (Vercel free + Supabase free + Clerk free) · ~$20/mo light · ~$70/mo growth · $200+/mo at scale. Anthropic API costs are usage-based on top.

Architecture seams already in place: content separated from rendering at content.json; skill specs are YAML frontmatter + markdown; no hardcoded user-specific paths in skill code.

Track 2

Browser-driven skills

Lighter version of the SaaS pivot: package each skill as a static page that runs Claude via the user's own API key, kept entirely in the browser. No server, no auth, no payments.

Lower bar than full SaaS. Friction: user must sign up for Anthropic API.

Track 3

In-browser code execution

Add a real SQL playground inside the PWA so retrieval problems can be self-checked. Likely path: DuckDB-Wasm runs SQL fully in the browser, no backend needed. Bundle gains ~3 MB.

Trade-off: DuckDB lacks some Trino/Postgres dialect features. Document divergences.

Track 4

Real spaced repetition

Replace the v0.1.0 flag-and-cooldown with SM-2 / Anki-style spaced repetition. Two new fields per problem (next_review_at, ease_factor). Anki-style 4-button rating after each retrieval attempt.

Worth it once content volume justifies it. The current flag-and-cooldown is sufficient for a 7-day prep horizon.

Track 5

Cross-application analytics

Each application's PWA is isolated today. A small analytics.json at project root could surface patterns across applications (e.g., topics you've struggled with in three of the last five prep sites become a flagged growth area on your resume).

Track 6

Auto-deploy on tagged release

CI today runs lint and smoke tests. CD is manual (Netlify Drop). On a tagged release, deploy a sample PWA to a preview URL — useful as a live demo for strangers.

Anti-roadmap

Things explicitly NOT planned, even with infinite time.

  • A native mobile app — PWA install is good enough.
  • A built-in chat with Claude inside the PWA — the toolkit's value is the structured workflow, not yet another chat box.
  • OCR for paper resumes — out of scope.
  • LinkedIn API integration — terms-of-service hostile.
  • "Auto-apply" features that submit applications — bad outcomes for users; we coach the application, the user submits.
